# jaehyun_words

AI 코딩 에이전트(Claude Code·Codex)와 일한 사람 메시지를 분석해 얻은 insight입니다. 원문 메시지, 단어 빈도 원표, 라벨 파일은 개인정보라 올리지 않습니다. 집계 수치와 정의, 해석만 담습니다.

## 어떻게 만들었나
- 분석 세션 네 개가 서로의 초안을 보지 않고 insight를 따로 썼습니다. 한 세션의 시각에 쏠리지 않게 하려는 것입니다. 이 문서는 그 네 초안을 합친 것입니다.
- 각 항목 끝의 **합의**는 네 초안 중 몇 곳에서 같은 결론이 나왔는지입니다. **확신**은 근거의 종류입니다. 수치로 잰 것은 높음, LLM 분류나 작은 표본은 중, 해석만 있는 것은 낮음입니다.

| 분석 | 방법 |
|---|---|
| 메시지 수집 | 사람이 직접 입력한 것만 남김. 자동 문구·주입문·도구 결과 제외. 규칙은 단위 테스트로 고정하고 테스트끼리의 모순은 Lean4로 검증 |
| 용어 | Kiwi 형태소 분석, 사용자 대 어시스턴트 log-odds 비교. 같은 입력 2회 실행 시 결과 해시 동일 |
| 메시지 성격·결정 | LLM 분류 → LLM 반박 검증 → 사람 표본 검수. 1,280건 |

## Insight

### 1. 사람은 고르고, 에이전트는 확인한다
사용자는 무엇을 왜 고를지, 어떻게 진행할지를 말합니다. 에이전트는 무엇을 확인했고 결과가 어떤지를 말합니다. 사용자 쪽으로 치우친 명사는 고려·판단·장단점·우위·최적·전략입니다. 에이전트 쪽은 확인·기록·결과·근거·통과·검사입니다.
합의 4/4 · 확신 중(명사만 셈, 맥락 없음)

### 2. "누가 할 일인가"를 자주 정한다
주체·위임·권한·허용이 사용자 특이어로 나옵니다. 결정은 사람이 하고, 도구와 에이전트는 조사·검증을 맡는다는 역할 분담이 대화에서 반복됩니다. 재현되는 규칙·코드·분석기는 주체가 아니라 장치로 봅니다. 재현되지 않는 모델만 주체로 셉니다.
합의 3/4 · 확신 높음

### 3. 묻기·시키기·정하기가 1/3씩이고, 의견이 결정만큼 많다

| 성격 | 뜻 | 수 | 비율 |
|---|---|---|---|
| 질의 | 묻기 | 416 | 32% |
| 지시 | 일을 시키기 | 392 | 31% |
| 결정 | 앞으로 지킬 것을 정하기 | 337 | 26% |
| 판정 | 의견·가설·평가, 고정하지 않음 | 314 | 25% |
| 통보 | 내가 한 일·상태를 알림 | 160 | 12% |
| 정보 제공 | 외부에서 가져온 것 | 35 | 3% |

한 메시지가 여러 성격을 가질 수 있습니다. 생각을 말로 풀어 가며 정하므로 "~할 수 있겠네" 같은 의견을 결정으로 읽으면 안 됩니다. 첫 분류에서 "규칙 제정"의 정확도가 60~65%에 그친 주원인이 이것이었습니다.
합의 2/4 · 확신 중상(LLM 분류값)

### 4. 결정은 대화 밖에서도 이뤄지고, 대화에는 통보로 온다
"이렇게 바꿨다"는 결정 행위가 아니라 통보입니다. 에이전트는 사용자가 직접 고친 기록과 자기 메모리를 맞춰야 합니다. 맞추지 못해 낡은 메모리가 남은 사례가 1건 확인됐습니다. 다른 사람이나 다른 AI의 의견을 전하는 말도 사용자 결정이 아니라 정보 제공으로 분리합니다.
합의 1/4 · 확신 중상

### 5. 뒤집기보다 범위를 좁히거나 다시 상기시킨다

| 결정 형태 | 수 |
|---|---|
| 새로 정함 | 237 |
| 승인 | 40 |
| 명확화 | 33 |
| 재확인 | 26 |
| 보류 | 11 |
| 변경 | 8 |

명확화와 재확인을 합친 수가 변경과 철회를 합친 수의 6배입니다. 상충처럼 보이는 것의 다수는 번복이 아니라 적용 범위를 말하지 않은 경우였습니다.
합의 1/4 · 확신 중

### 6. 판단 기준의 약 2/3는 규칙으로 검사할 수 있다
결정을 결정 템플릿의 칸으로 나눴습니다.

| 칸 | 뜻 | 수 |
|---|---|---|
| action | 대상에 무엇을 할지 | 207 |
| 기준(규칙) | 규칙으로 검증할 수 있는 기준 | 115 |
| selector | 적용 대상·범위 | 111 |
| 기준(그 외) | 우선순위·중요도처럼 규칙으로 검증할 수 없는 기준 | 58 |

규칙으로 검사할 수 있는 기준은 에이전트에게 맡깁니다. 사람의 검토는 규칙으로 닫히지 않는 판단과, 규칙끼리 함께 설 수 없을 때 하나를 고르는 일에 집중시킵니다(13번). 사용자도 세션 간 일관성을 "의견이 맞는가"가 아니라 "같은 규칙이 적용되는가"로 봅니다. 정답이 없는 일(이름 짓기, 화면 설계)을 하는 작업일수록 규칙으로 검증할 수 없는 기준의 비중이 큽니다. 그런 작업은 약 20%이고, 실험 작업은 약 9%입니다.
합의 3/4 · 확신 중(표본 16건 중 13건 타당, 작업별 비교는 n이 작음)

### 7. 일하는 순서: 규칙과 재현 먼저, LLM은 마지막
- 규칙 기반·재현 가능한 실험을 먼저 하고 LLM은 결과 해석에만 씁니다.
- 테스트가 구현보다 중요합니다. 테스트끼리 함께 설 수 있는지는 수학 모델(Lean·Wolfram)로 검증합니다.
- 확인할 수 있는 것은 묻지 말고 먼저 재 봅니다.
- 예외를 나열하기보다 한 번에 범위와 규칙으로 설명되게 합니다.

합의 3/4 · 확신 높음(사용자가 명시)

### 8. 수정 프로토콜: 비교해서 나을 때만 바꾼다
사람이 눈으로 확인할 수 있어야 최소 기능 제품입니다. 로컬·웹·새로 만든 것을 비교해 우위가 확인된 것만 씁니다. 확실한 것부터 고정하되, 고정은 통제를 쉽게 하려는 것이라 전체 일관성을 위해 바꿀 수 있습니다. 이름도 새로 짓기보다 기존에 쓰이는 말에서 먼저 찾습니다.
합의 3/4 · 확신 높음

### 9. 반복은 강조의 신호다
사용자는 같은 지시를 반복하고, 반복을 "더 중요하다"는 신호로 봅니다. 반복을 지우면 상위 용어 40개 중 3개가 바뀝니다. 그래서 분석에서 반복을 기계적으로 지우지 않습니다.
합의 1/4 · 확신 높음(사용자 확인과 측정)

### 10. 짧고 쉬운 말, 업계에서 통하는 말
- 설명은 짧고 쉽게, 한 일과 안 한 일을 분명히 하길 원합니다.
- 이름은 직업 이름 꼴의 짧은 업계 통용어를 선호합니다.
- LLM에게 주는 입력에서는 개발·형식 용어를 뺍니다. 선택지 자체가 신호가 되기 때문입니다.
- 구어체 습관으로 얘기·일종·이슈·노하우가 사용자 특이어로 나옵니다. "갯수"는 사용자가 29회, 에이전트가 1회 썼습니다. 에이전트는 "개수"를 씁니다. "말씀"은 사용자 1회, 에이전트 1,527회입니다.

합의 2/4 · 확신 중상

## 추가 분석: 사용자는 무엇을 궁금해했나 (2026-11-12)

범위는 작업 세션 세 개의 사람 메시지 1,369건입니다(실험 하네스 1,213 · 신규사업 검토 측정 76 · 결과 엑셀 제작 80). 붙여넣기, 사람이 쓰지 않은 자동 문구 4건, 모델 전환 같은 앱 명령 83건은 뺐습니다. 위 3번 표(1,280건)와는 범위가 달라 숫자를 직접 비교하지 않습니다.

방법: 규칙(물음표, 모른다는 표현)으로 후보 570건을 고르고, LLM 분류 → LLM 반박 검증(26건 수정) → 표본 검수 순으로 했습니다.

### 11. 가장 많은 궁금증은 "내가 이해한 것이 맞는가"다
후보 570건 가운데 궁금증이 459건(메시지의 34%), 반문이 35건, 해당 없음이 76건입니다. 반문은 물음 형식이지만 답을 이미 아는 지적·재촉입니다.

| 궁금증 주 유형 | 알고 싶은 것 | 수 | 비율 |
|---|---|---|---|
| 이해 확인 | 내가 이해한 것이 맞는지 | 94 | 20% |
| 의견 요청 | 에이전트의 판단·추천 | 61 | 13% |
| 진행 상태 | 했는지, 끝났는지 | 48 | 10% |
| 수치·개수 | 개수·비율·점수 | 48 | 10% |
| 출처·위치 | 어느 파일·표·세션에 있는지 | 42 | 9% |
| 정의·용어 | 말·개념의 뜻 | 38 | 8% |
| 원인·근거 | 왜 그런지, 무엇이 근거인지 | 38 | 8% |
| 방법·절차 | 어떻게 하는지 | 37 | 8% |
| 가능 여부 | 할 수 있는지 | 32 | 7% |
| 비교·차이 | 둘 이상의 차이·우열 | 11 | 2% |
| 기타 | | 8 | 2% |
| 책임·주체 | 누가 했는지 | 2 | 0.4% |

- 이해 확인·진행 상태·수치·출처를 합치면 사실과 상태를 확인하는 질문이 232건(51%)입니다. 새 개념을 묻는 질문(정의·용어)은 8%입니다. 에이전트는 설명보다 파일·수치·상태처럼 확인할 수 있는 사실로 답해야 합니다.
- 의견 요청(13%)은 결정 이전 단계입니다. 이 질문에 대한 답을 사용자 결정으로 기록하면 안 됩니다.
- 반문은 답할 질문이 아니라 고칠 일입니다. 이미 정한 규칙을 어긴 데 대한 지적이 대부분이어서, 교정과 재발 방지 기록이 맞는 대응입니다.
- 궁금증의 10%(47건)는 물음표 없이 나옵니다. 물음표만 세면 놓칩니다.
- 키워드 규칙은 후보를 고르는 데만 씁니다. 규칙이 낸 유형이 최종 유형과 맞은 비율은 39%이고, 규칙이 유형을 내지 못한 비율은 48%입니다.

확신 중(LLM 분류값). 분류 세션의 표본 45건 중 38건 일치(84%). 별도로 유형별 층화 표본 72건을 다시 봤을 때 궁금증·반문·해당 없음 구분은 72건 모두 일치했고, 주 유형은 56건 중 53건이 일치했습니다. 두 검수 모두 에이전트가 했고 사람 검수는 아직입니다.

### 13. 판단은 세 단으로 나누고, 이름은 판정 전과 후를 구분한다
사용자가 정한 판단 분담입니다.

| 단 | 맡는 쪽 | 대상 |
|---|---|---|
| 1 | 컴퓨터 | 규칙으로 확실히 판단할 수 있는 것 |
| 2 | AI가 돕고 사람이 확정 | 의미 판단 중 기존에 내린 결정(선례)이 있는 것. AI는 선례를 근거로 제안만 함 |
| 3 | 사람 | 선례가 없는 의미 판단, 규칙끼리 함께 설 수 없는 경우 |

규칙끼리 부딪치는 경우는 세 단계 이름으로 나눕니다.

| 단계 | 이름 | 뜻 | 맡는 쪽 |
|---|---|---|---|
| 탐지 | 불일치 | 같은 입력에 규칙들이 다른 출력을 냄. 판정 전의 사실 | 컴퓨터 |
| 판정 | 공존가능성 | 적용 범위·의도를 보고 함께 설 수 있는지 의미로 따짐 | 선례 있으면 AI 보조, 없으면 사람 |
| 결과 | 공존 / 모순 | 공존이면 적용 범위를 규칙에 적고, 모순이면 하나를 고름 | 모순은 사람 |

- "모순"은 판정이 끝났다는 뜻을 담은 말이라 맨 끝 결과에만 씁니다. 상충처럼 보였던 것의 다수(5번)는 탐지 단계의 불일치였고, 판정 결과는 적용 범위가 다른 공존이었습니다.
- 증명가능성(개별 판단이 규칙에서 엄밀히 끌어내지는가)은 1단을 가르는 기준이며, 형식 검증 비용이 커도 된다는 것이 사용자 판단입니다.
- 이름은 사용자가 익숙하게 쓰는 개념이면 사용자 말에 맞추고, 다르게 써야 하는 개념이면 사용자 말과 다르게 짓습니다. 사용자 메시지에서 "불일치"는 17회 모두 판정 전의 차이를 뜻해 그대로 썼고, "충돌"(10회)은 판정 전과 후 두 뜻에 섞여 단계 이름에서 뺐습니다.

합의 1/4 · 확신 높음(사용자가 명시, 단어 횟수는 측정)

## 방법에서 배운 것
- **단순 빈도로는 사용자 고유 어휘가 안 보인다.** 상위는 사용·진행·확인·필요 같은 일반어입니다. 세션 단위 TF-IDF로도 거의 빠지지 않습니다. 어시스턴트 답변 같은 외부 기준과 비교해야 드러납니다.
- **Kiwi는 사용자 사전이 결정적이다.** 업무 복합어 19개가 한 단어로 남은 수입니다.

| 설정 | 남은 수 |
|---|---|
| 기본 모델 | 13 |
| 전역 문맥 모델 | 11 |
| 사용자 사전 추가 | 19 |

  오타 교정, 받침 정규화, 복합어 분해 옵션은 거의 차이가 없었습니다. 붙여 쓴 명사를 결합하면 5글자 이상 용어가 크게 늘어 과결합일 수 있습니다. 이 부분은 검수하지 않았습니다.
- **승인은 짧아서 앞 문맥이 필요하다.** "진행해" 같은 한두 단어 승인은 직전 에이전트 제안과 묶어야 분류됩니다. 사람 메시지만 모으면 의도 분석에 한계가 있습니다.
- **사람 메시지 추출에 자동 문구가 약 1% 섞인다.** 세션 간 알림, 사용량 한도 재개 문구, 예약 점검이 그것입니다. 의도 분석 전에 걸러야 합니다.

## 한계
- 용어 분석은 명사만 셌습니다. 동사, 부정, 말투의 높낮이는 빠졌습니다.
- 사용자와 에이전트의 분량 차이가 약 35배라 사용자 쪽 드문 단어는 우연의 영향이 큽니다.
- 메시지 성격과 결정 칸 수치는 LLM 분류값입니다. 사람 검수는 표본으로만 했습니다.
